# Hai Audit Docs Internally 中文版

本文件是中文阅读版；执行规则以 `SKILL.md` 为准。

## 概览

用这个 skill 从文档内部审计单个文档或文档集。真相来源不是代码，而是文档自己的目标、结构、术语、声明和交叉引用。

## 核心原则

把文档当成一篇连贯论证：

- 文档应该有清晰目的和受众。
- 各 section 应该服务同一个目标。
- 定义、术语、假设、流程和示例不应互相矛盾。
- 重复内容要么有意强化，要么应该合并。
- 过期或无依据内容应该更新、移动、标成开放问题或删除。
- 不要对照代码审计；需要文档和代码一致性时使用 `hai-audit-docs-against-code`。

## 工作流

1. 明确文档范围：单篇文档、相关文档集、PRD 包、README + docs 或生成规格。
2. 建立文档地图：列出 section、关键声明、定义、术语、假设、范围、示例、状态和交叉链接。
3. 找内部问题：直接冲突、范围冲突、术语漂移、生命周期冲突、验收冲突、过期信号、重复内容、错位内容、无依据声明。
4. 决定修复类型：更新、移动、合并、删除、拆分或提问。
5. 输出审计，优先处理会改变理解、决策、范围或执行的问题。

## 严重级别

| 级别 | 含义 |
|------|------|
| P0 | 内部冲突可能导致错误决策、不安全行动或发布失败 |
| P1 | 核心目标、范围、术语或验收不一致 |
| P2 | 过期、重复、错位或无依据内容造成混乱 |
| P3 | 轻微清晰度、结构或格式问题 |
| Needs decision | 需要负责人决策才能解决 |

## 不是什么

- 不是文档对代码审计。
- 不是 PRD 专项打磨；PRD 用 `hai-prd`。
- 不是 README 排版美化。
