# Hai Goal 中文版

本文件是中文阅读版；执行规则以 `SKILL.md` 为准。

## 概览

用这个 skill 在真正执行前先写 goal document，防止“一边跑一边看”。Goal document 是一个以目标为中心的计划：定义什么应该变成真、如何分阶段、每个阶段有什么规则、如何验证完成。

它也处理已有计划的重写：当用户给了一个目标，并要求围绕该目标重写计划时，保留有用内容，删除局部噪音，重排优先级，把旧计划变成更强的 goal document。

## 核心原则

先写 Goal，再 Go。

不要一上来写代码、改文件或边探索边等目标变清楚。大多数工作都应该先写成包含可验证目标、边界、阶段、规则、todo、依赖和 proof 的 goal document。

## 模式

- **Make goal**：把模糊意图变成清晰、可验证的目标。
- **Craft goal**：把目标拆成阶段、todo、依赖和证明。
- **Rewrite around target**：围绕指定目标重写已有计划。
- **Go document**：执行前先把路线写清楚。

## 工作流

1. 冻结意图：用户想开始什么？什么结果值得做？什么不能破坏？还有什么未知？
2. 让目标可验证：把活动改写成结果，定义边界、证据来源、通过/失败标准。
3. 转成 goal document：记录假设、未决问题、影响面和可执行条件。
4. 如有旧计划，围绕目标重新锚定：诊断目标漂移、阶段漂移、验证漂移、兼容性漂移、清理漂移。
5. 拆阶段：按风险、学习、用户价值、依赖、边界或验证切分。
6. 定义阶段规则：允许什么、暂不允许什么、需要什么验证。
7. 创建 todos：每个 todo 都要有 action、surface、proof。
8. dry-run 路线：找缺失前提、循环依赖、模糊 todo 和未验证假设。
9. 给出 Go / No-Go 判断。

## 输出要求

返回 goal document，而不是泛泛建议。应包含目标结果、开放问题、边界、验证规则、优先级理由、阶段、规则、todo、阶段验证和 Go / No-Go。
