# Hai Audit Docs Against Code 中文版

本文件是中文阅读版；执行规则以 `SKILL.md` 为准。

## 用途

对照代码、配置、schema 与 API 契约，找出文档中过时、不一致或遗漏的声明。每个 finding 都给文档位置、实现/契约证据、影响和最小诚实修复；审计同时走文档→实现与实现→文档两个方向。

## 核心原则

1. **先声明证据优先级。** 当前实现证明现在实际运行什么；已批准 PRD/spec 可以定义目标行为；公共契约与持久化 schema 约束可改范围。出现差异不等于文档必错。
2. **权威源优先于派生产物。** 使用 OpenAPI、protobuf、GraphQL、DB schema 或类型前，先判断谁是生成物、谁是 canonical source。
3. **安全相关提高优先级。** 权限、沙箱、隐私、计费和破坏性操作的错误说明风险更高。
4. **有证据再判断。** 每个问题同时给文档位置和实现/配置/契约证据。
5. **围绕使用场景审。** 按 quickstart、API 集成、配置、权限、生命周期或领域实体组织，不做松散逐文件扫雷。

## 工作流

1. 明确文档声称的是当前行为、目标行为还是公共承诺，并记录各类声明的权威来源；无法确定时标记 Needs evidence/decision。
2. 用户指定文件时只审指定范围；未指定时才看 README、`docs/**/*.md`、API 文档、示例、安装说明和生成文档。
3. 提取 3–8 个真实使用场景作为审计主题。
4. 文档→代码：按 `references/checklist.md` 提取行为、命令、默认值、字段、端点、权限、配置和示例，并搜索对应实现。
5. 代码→文档：从契约、配置、路由、CLI、公共类型和测试寻找文档遗漏或误述的用户可见行为。
6. 使用 `references/output-template.md` 输出按严重度排序的 findings；证据不足就保留为 Needs evidence，不夸大。

## 严重度

| 级别 | 含义 |
|------|------|
| P0 | 安全问题或会导致危险操作的严重误导 |
| P1 | 核心流程、安装或集成按文档执行会失败 |
| P2 | 非阻塞的命名、字段、示例或默认值漂移 |
| P3 | 低影响链接、措辞或格式问题 |
| Needs evidence | 有合理怀疑但权威来源或证据不足 |

安全、权限、隐私、计费和破坏性操作至少提高一级处理优先级。

## 输出与路由

每项写严重度、文档位置、权威来源、实现/契约证据、影响、最小修复和修复收益；结尾给 verdict、数量和修复顺序。需要校准“当前行为 vs 目标行为”时读取 `references/worked-examples.md`。

- 只审文档内部矛盾：`hai-audit-docs-internally`。
- 对照 PRD 审实体字段：`entity-model-auditor`。
- 用户要重写漂移文档而不是 findings：`hai-rewrite-doc`。
