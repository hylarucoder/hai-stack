# Hai Audit Docs Against Code 中文版

本文件是中文阅读版；执行规则以 `SKILL.md` 为准。

## 目标

系统性找出 README 和文档中所有过时、错误，或与代码实现、配置、API 合同不一致的描述，并给出证据。

## 核心原则

1. **以代码为真**：文档与实现冲突时，以源码、配置和合同文件为准。
2. **有证据再下结论**：每个问题都要有文档位置和实现/配置/合同证据。
3. **合同优先**：OpenAPI、proto、GraphQL schema、数据库 schema、TypeScript types 都是强真相来源。
4. **安全默认收紧**：权限、沙箱、隐私、计费、破坏性操作优先提高严重级别。
5. **按场景审计**：围绕真实使用场景组织问题，不做松散扫雷。
6. **说明修复收益**：每个建议都要说明修完能减少什么误用、返工或 onboarding 成本。

## 工作流

1. 枚举文档范围：README、`docs/**/*.md`、API 文档、示例、配置文档、合同文件。
2. 提炼 3-8 个审计主题：快速开始、API 集成、环境变量、安全权限、生命周期、领域实体等。
3. 逐文档抽取关键声明，并在代码/配置/合同中找对应证据。
4. 从实现反查文档，发现遗漏或错误说明。
5. 输出审计报告，使用 `references/output-template.md` 和 `references/output-format.md`。

## 严重级别

| 级别 | 含义 |
|------|------|
| P0 | 安全或严重误导 |
| P1 | 核心流程不一致，按文档操作会失败 |
| P2 | 示例、命名、默认值等非阻断性过时 |
| P3 | 小的措辞、格式或链接问题 |
| 待证据补充 | 有怀疑但证据不足 |

## 输出要求

每个问题项必须包含严重级别、文档位置、代码/配置/合同证据、影响、最小修复建议、修复收益和关联原则。
