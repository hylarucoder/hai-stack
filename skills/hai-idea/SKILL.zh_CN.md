# Hai Idea 中文版

本文件是中文阅读版；执行规则以 `SKILL.md` 为准。

## 概览

用这个 skill 判断一个想法到底值不值得占用注意力。

它不是用来礼貌地夸想法，也不是列一堆平均主义的优缺点。它要做的是把决策说清楚：这个想法应该做、先验证、重塑、延后，还是直接砍掉。

## 核心原则

大胆判断，小心求证。

要给明确结论，但结论必须绑定证据。不要躲在“有利有弊”里面。如果想法的用户不清、痛点不硬、成本过高、时机不对、没有验证路径，就直接说。

## 何时使用

- 这个想法是不是好主意？
- 值不值得做？
- 要不要做、写、构建、发布、投入时间？
- 这几个想法哪个更值得？
- 是否应该变成 goal、PRD、实验或 backlog？
- 这是不是一个分散注意力的东西？

## 判断维度

- **痛点**：是否高频、紧急、昂贵，或情绪上尖锐？
- **对象**：谁具体受益？
- **现状替代方案**：现在怎么解决？是否已经够用？
- **杠杆**：是否能复用、复利、降低未来成本？
- **时机**：现在是否合适？是否被基础设施、需求、信任、数据或分发卡住？
- **差异性**：为什么不是普通复制品或局部偏好？
- **可行性**：当前资源是否能做？
- **成本**：消耗时间、注意力、维护、复杂度还是声誉？
- **风险**：可能如何失败或让后续更难？
- **证明路径**：什么证据会让想法变强或变弱？

## 工作流

1. 用一句话重述想法。
2. 明确当前决策：做、验证、排序、重塑还是砍掉。
3. 只评价真正影响决策的维度。
4. 给出明确结论：做、先验证、重塑、延后、砍掉。
5. 定义最小有效验证。
6. 需要下一步时，转向 `hai-goal`、`hai-prd`、`geju` 或 `hai-naming`。
