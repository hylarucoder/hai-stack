# Goudi / 苟帝

中文版本用于阅读和文案打磨。执行规则以英文 `SKILL.md` 为准。

## 概览

这个 skill 用在方案讨论已经太宏大、太抽象、太想一步到位的时候。`goudi` 几乎是 `geju` 的反面搭档：`geju` 负责把格局打开，`goudi` 负责把路踩实。

它不是保守派，也不是反重构。它的作用是让一个大方向变得可执行、可验证、可止损，并且能在下一步产生真实进展。

## 核心原则

先把路踩实，再谈大胜利。

可以有大想法，可以有彻底重构，可以有强架构判断。但一个有用的方案必须回答：

- 最小证明动作是什么？
- 什么证据说明方向是对的？
- 哪些真实约束会把它打爆？
- 第一阶段应该主动砍掉什么？
- 如果判断错了，什么时候停？

如果一个方案说不清楚第一步怎么做，它还不是计划，只是一种情绪。

## 和 Geju 的关系

当 Codex 被局部细节、兼容性焦虑、小修小补困住时，用 `geju`。

当回答已经飞得很高，但缺少可执行路径、验证规则和止损机制时，用 `goudi`。

这两个 skill 是一对：

- `geju` 问：“如果不害怕，我们真正应该做什么？”
- `goudi` 问：“这个方向接触现实后的第一个证明点是什么？”

不要让 `goudi` 抹掉大目标。它压缩的是第一步，不是野心。

## 要对抗的问题

### 1. 有愿景，没有第一步

方案听起来都对，但今天下午不知道该改哪个文件、写哪个测试、验证什么结果。

反制动作：

- 点名第一个具体产物：测试、PRD 修改、接口变更、迁移 spike、原型、benchmark、审计或决策记录。
- 定义第一步的精确范围。
- 明确哪些东西第一步不做。

### 2. 假迁移计划

目标模型很干净，但路径默认所有东西可以一次改完。

反制动作：

- 找出现有真实契约：持久化数据、公开 API、用户流程、部署、合规、团队 owner、已文档化集成。
- 把目标设计和迁移路径分开。
- 优先做一个窄的纵向切片，而不是大面积半成品改造。
- 找出不可逆动作，并在证据不足时延后它。

### 3. 风险没有定价

回答轻飘飘地说“可以重构”，却没有评估数据丢失、行为变化、影响面、测试缺口和隐藏调用方。

反制动作：

- 列出影响面最大的 3 个风险。
- 每个风险都给验证方法。
- 判断哪个风险必须先消掉。
- 拒绝无法在合理反馈周期内验证的工作。

### 4. 长期正确，短期不负责任

方向可能是对的，但现在全量做会拖垮当前目标。

反制动作：

- 区分终局和下一个里程碑。
- 判断下一个里程碑是否即使没有完成终局，也能让系统更正确。
- 砍掉漂亮但不必要的工作。
- 在信心不足时保留选择权。

### 5. 没有止损规则

计划只能继续，不能体面失败。

反制动作：

- 开始前定义失败信号。
- 定义回滚或隔离方式。
- 定义什么时候暂停并补证据。
- 不接受因为已经投入而继续硬推。

## 工作流

1. 用一句话复述大方向。
   - 不要把野心磨平。
   - 说明它来自 `geju`、PRD、架构审查还是用户想法。

2. 做现实检查。
   - 哪些真实契约限制了这件事？
   - 哪个系统区域影响面最大？
   - 哪些假设还没被证明？
   - 方案里哪些部分只是好看、猜测或过早？

3. 选择最小可行推进。
   - 只选一个窄切片、证明点或决策产物。
   - 定义它改什么，也定义它拒绝改什么。
   - 优先选择能产生证据的动作，而不是继续写更多计划。

4. 明确验证规则。
   - 成功标准必须可观察。
   - 失败信号必须提前命名。
   - 验证成本要低。
   - 如果涉及行为实现，连接 `hai-tdd`。

5. 激进砍范围。
   - 列出第一步不应该尝试的东西。
   - 砍掉没有真实契约支撑的兼容工作。
   - 砍掉不影响证明点的架构打磨。
   - 在窄切片证明前，不做大迁移。

6. 定义止损规则。
   - 什么证据会推翻或暂停这个方向？
   - 什么情况说明目标要缩小？
   - 什么东西可以回滚或隔离？
   - 哪个决策现在不要做？

7. 输出前读取 `references/output-template.md`。

## 输出规则

- 开头先给落地判断：推进 / 缩小 / 暂停 / 拒绝 / 先验证。
- 第一动作必须具体。
- 写清楚第一阶段砍什么。
- 写清楚成功标准和失败信号。
- 把真实约束和焦虑惯性分开。
- 保留有价值的大目标，但不要让大目标代替执行。
- 不要写巨大的计划；需要完整阶段和 todo 时交给 `hai-goal`。
- 不要把 `goudi` 变成“什么都别做”。默认是缩小验证，不是原地瘫痪。

## 它不是什么

- 不是 `geju`。它不负责打开格局，而是让已经打开的格局落地。
- 不是通用项目管理。它专门审判方案能不能落地。
- 不是反重构。它反对的是幻想迁移，不是干净目标。
- 不是 TDD 本身。需要用测试定义行为时使用 `hai-tdd`。
- 不是完整 goal 文档。需要 phases、todos 和执行跟踪时使用 `hai-goal`。
